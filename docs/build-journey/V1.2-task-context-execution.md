## Architecture, lifecycle and security

One Python execution owner behind `jous_supply`; one logical model and route;
one application dispatch; no retry or fallback. Claim commit must be confirmed
before local dispatch authority exists. Revalidate permission/project/route and
deadline in a fresh short transaction, release the connection, then perform
supplier I/O. Reauthorize finalization in another transaction and return only a
persisted result. Uncertain commit, lost response, crash, timeout or finalization
failure never authorizes redispatch. An expired outcome-less claim is derived
UNKNOWN; no outcome row is manufactured after a crash.

`task.execute` is additive and initially active-owner-only; `project.read` is
insufficient. Do not alter frozen Action/ROLE_ACTIONS. Server owns organization,
actor, endpoint, native model and admission evidence. Explicit DTOs exclude
internal bindings, hashes, context packages and provider request IDs. Provider
text is untrusted display data; credentials/raw envelopes/reasoning are not stored.

ContextPackage v1 contains only the versioned server instruction and authorized
project/current-task snapshot with per-element provenance. Prompt 8 KiB, optional
task context 16 KiB, canonical package 32 KiB, incoming body 64 KiB, supplier
envelope 1 MiB, retained text 64 KiB. Reject overflow; never truncate silently.
